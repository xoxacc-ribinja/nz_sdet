# Task 21 — Сколько неудачных прогонов до успеха

Дата публикации контракта: 2026-10-14. Начинать реализацию **после слияния документа в main**.

## Зачем
Небольшая самостоятельная задача на цикл, локальные переменные и return. Ориентир 20–35 минут, без обязательной нормы времени. Новых конструкций не требуется.

## Функция
Файл: `week04/solutions/python_core_21.py`.

```python
def failures_before_success(results: list[bool]):
    ...
```

- `results` — хронологический список результатов запусков: `False` = ошибка, `True` = успех.
- Вход **всегда корректен**: это список, и все элементы имеют тип `bool`. Валидация, исключения и обработка иных типов **не требуются**.
- Вернуть количество `False` **до первого `True`** как `int`. Всё после первого `True` игнорировать.
- Если `True` нигде нет, в том числе если список пуст, вернуть `None`.
- Не печатать ничего, не менять исходный список, не использовать глобальные переменные.
- Примеры: `[False, False, True, False]` → `2`; `[True, False]` → `0`; `[False, False]` → `None`; `[]` → `None`.
- Реализация свободная. `enumerate`, генераторы, специальные библиотеки или иной незнакомый синтаксис не обязательны.

## Тесты и сдача
Создать `week04/solutions/test_python_core_21.py` с небольшим набором pytest-тестов на **четыре ситуации**: успех сразу, успех после неудач, нет успеха, пустой список. Нет задачи на десятки комбинаций. Тест неизменности исходного списка допустим, но отдельная тестовая группа не обязательна.

Запускать из корня репозитория:

```bash
python -m pytest week04/solutions/test_python_core_21.py -v
```

После слияния документа создать свою ветку от `main`, отправить только решение и тесты через отдельный PR, приложить реальный лог запуска; краткая защита алгоритма — в чате. Если нужны подсказки, сообщить; помощь учитывается отдельно от корректности.

## PASS — неизменные критерии
1. Функция выполняет **весь описанный контракт** на допустимых входах, возвращает нужное число либо `None`, не печатает и не мутирует список.
2. Собственные pytest-тесты охватывают четыре названные ситуации и проходят локально.
3. Есть PR, реальный лог pytest и объяснение ключевой логики на защите.
4. Нельзя добавлять ретроспективные обязательные требования о валидации, конкретном синтаксисе, дополнительных типах или многочисленных тестах.

Скрытые проверки после защиты возможны **только по этому контракту**; ассистент сообщает, были ли они фактически запущены. PASS задним числом не пересматривается.
