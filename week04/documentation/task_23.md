## Контракт функции
Создать `week04/solutions/python_core_23.py`:

```python
def count_failures_by_suite(runs: list[dict]) -> dict[str, int]:
    ...
```

Вход всегда корректен: список словарей, у каждого словаря есть ровно два обязательных ключа: `"suite"` (непустая строка) и `"passed"` (`bool`). Дополнительные ключи допустимы, их игнорировать. Проверка типов и исключения **не требуются**.

Нужно вернуть **новый** словарь, в котором для каждого уникального имени `suite` записано количество прогонов с `passed is False`.

- Каждая `suite`, встретившаяся хотя бы раз, обязательно присутствует в результате, **даже если все её прогоны успешны** (значение `0`).
- Повторяющиеся записи одной `suite` учитываются отдельно.
- Сравнение имён точное: `"API"` и `"api"` — разные ключи.
- Порядок пар в словаре не является отдельным критерием проверки.
- Если `runs` пуст, вернуть `{}`.
- Нельзя мутировать `runs` или его внутренние словари, использовать глобальное состояние или выводить что-либо на экран.

Примеры:

```python
[
    {"suite": "API", "passed": True},
    {"suite": "UI", "passed": False},
    {"suite": "API", "passed": False},
    {"suite": "UI", "passed": False},
]
# Ожидается {"API": 1, "UI": 2}

[
    {"suite": "API", "passed": True},
    {"suite": "API", "passed": True},
]
# Ожидается {"API": 0}

[]
# Ожидается {}
```

**Ловушка для внимательности:** имя `suite` должно оставаться в результате при нулевом числе ошибок. Поведение отсутствующего ключа и уже существующего ключа со значением `0` не следует путать. Это не дополнительное скрытое требование, а часть зафиксированного контракта.
