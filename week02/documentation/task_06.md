# Task 06 — VM Health Check (исторический контракт)

**Источник:** задание в учебном чате, 2026-09-29. Восстановлено задним числом для документирования истории, **не является новым заданием или пересмотром PASS**.

## Вход

Файл `vm_health.txt`, исходные строки:

```text
win-build-01,running,72
linux-test-01,stopped,0
mac-build-01,running,91
win-test-02,running,48
linux-build-02,error,0
mac-test-02,running,91
old-runner,unknown,15
broken-vm
```

Формат корректной строки: `vm_name,status,cpu`. Допустимые статусы — `running`, `stopped`, `error`. Строка невалидна, если `split(',')` даёт не три поля или статус неизвестен. **Проверять числовую корректность CPU не требовалось**, но у корректных строк CPU преобразуется в `int`.

## Ожидаемый вывод

```text
Valid VMs: 6
Invalid lines: 2

By status:
running: 4
stopped: 1
error: 1

Highest CPU: 91
VMs with highest CPU:
- mac-build-01
- mac-test-02

Invalid input:
- old-runner,unknown,15
- broken-vm
```

Максимальное CPU могут иметь несколько машин — вывести все.

## Ограничения и критерии PASS из первоначального задания

- Минимум **четыре функции**.
- Разрешённые изученные инструменты: `list`, `dict`, `for`, `if/elif/else`, функции/аргументы, `split`, `len`, `in`, `int`.
- Не использовать `class`, `set`, `Counter`, `max()`, `sort()`, внешние библиотеки.
- Прочитать `vm_health.txt` **ровно один раз за запуск**; функции подсчёта и форматирования не открывают файл повторно.
- PASS: 6 valid, 2 invalid, счётчики статусов 4/1/1, CPU максимум 91 у двух указанных VM, обе исходные ошибочные строки, однократное чтение файла.
- Первые 20 минут — без просмотра решений Tasks 03–05; после разрешался просмотр синтаксиса с указанием подсказок. Ориентир 45–60 минут.
- AI мог объяснять синтаксис или сообщение об ошибке, но не писать алгоритм.
