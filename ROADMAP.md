# Roadmap — Python Core → самостоятельный Automation QA / SDET

**Актуализировано 16.10.2026.** Это последовательность **учебных тем**, а не политика поведения. Правила занятий — только [AGENTS.md](AGENTS.md); текущая точка — [PROJECT_STATE.md](PROJECT_STATE.md); доказательства — [LEARNING_LOG.md](LEARNING_LOG.md).

## Цель

Сформировать самостоятельного инженера, способного объяснить и изменить свой код, расследовать дефект, написать тесты и пройти реальное техническое интервью без замещения работы AI. Конечный профессиональный контекст — конкурентоспособность для поиска Auto QA/SDET в Новой Зеландии; планы релокации **не являются критериями PASS** Python-задач.

## Текущий этап: до ноября 2026 — Python Core

Изучено или применялось в задачах (глубина не равна освоению): `if/elif/else`, циклы, строки, списки/словари, функции и возвраты, проверки границ, базовые аннотации, элементы парсинга, `try/except`, ранее — основы pytest. Умение быстро написать знакомую функцию на `dict` подтверждено; нюанс `dict.get()`/`0` и независимое удержание ряда механизмов остаются рисками.

**Далее при возобновлении занятий, не все одновременно:**
1. Работа с файлами, `pathlib`/относительные пути, `with`, чтение/запись без хардкода локальных путей.
2. JSON/CSV, проверка и преобразование данных; обработка ошибок, `try/except/else/finally` в реальном сценарии.
3. Композиция функций, модули, импорты, небольшая структура программы, разделение ответственности.
4. Базовое ООП **после объяснения**: объект, конструктор, состояние, методы, затем композиция и наследование там, где полезно.
5. По необходимости для самостоятельной маленькой программы: `venv`/`pip`, `argparse`, `logging`, базовый `typing`, `pathlib`.
6. Интеграционная неизвестная Python-задача и независимая защита как **диагностика**, без автоматического PASS по календарю.

Это **не жёсткий порядок уроков или навязанный дедлайн**. Чередовать учебную новизну, перенос и короткое повторение, не возвращать фиксированные квоты `60/40` или `25/50/25`: они исторически отменены. Не ставить очередной десятый парсер/агрегатор как замену изучению новой темы. Новое объяснять перед задачей.

## Позже — только после оценки фактической подготовки

- pytest: самостоятельный выбор сценариев, fixture, parametrization, raises, исправление сломанных тестов, отладка и тест-дизайн.
- HTTP/API automation, затем SQL для проверки данных, UI Playwright.
- Git workflow и CI: запуск, артефакты, диагностика failures и flaky tests.
- Системная автоматизация на близких профессиональных контекстах: VM, процессы, логи, ОС, Packer/скрипты.
- Портфолио, mock interviews и технический английский — по отдельному согласованию.

**Не путать введение нового инструмента с реальным владением им.** Навык подтверждается самостоятельным решением, объяснением, работой после перерыва и переносом в другой контекст. Отчёты и тестовые счётчики лишь доказательства, не цель.

## Нагрузка и контроль

Гибкий ориентир ~12 часов в неделю без долга за пропущенные занятия. Учебные вопросы и новые задания — **только когда ученик хочет заниматься**. Проверка прогресса: конкретное «раньше → сейчас → самостоятельное доказательство → не проверено»; никаких искусственных оценок/вероятностей готовности. Python Gate конца ноября — историческая диагностическая идея, а не обязательный дедлайн.
