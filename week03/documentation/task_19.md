## Часть A — SDET: стоимость облачного хранилища

Готовая функция находится в `week03/input_files/storage_billing.py`:

```python
calculate_storage_cost(used_gb: int, free_gb: int, price_per_gb: int) -> int
```

**Контракт:**

- Все три аргумента — целые числа `int`, **не `bool`**, и неотрицательные.
- `used_gb` — фактическое использование; `free_gb` — бесплатная квота; `price_per_gb` — стоимость каждого гигабайта сверх квоты.
- Если `used_gb <= free_gb`, результат `0`.
- Если `used_gb > free_gb`, результат `(used_gb - free_gb) * price_per_gb`.
- При любом неверном типе или отрицательном аргументе функция должна выбросить `ValueError`.
- Возвращаемое значение — целое число, без округления.

**Задача:** самостоятельно написать тесты в `week03/solutions/test_storage_billing.py`, основываясь на контракте, а не на фактическом поведении реализации.

**Обязательные группы тестов:**

1. Использование ниже квоты, **ровно на квоте**, выше квоты (в том числе на 1 ГБ).
2. Случай с нулевой ценой за гигабайт и корректные нулевые значения.
3. Отрицательные аргументы.
4. Некорректные типы, в том числе `bool`.

Исходник может содержать дефект. Если тест выявит расхождение, объясни его; **не исправляй предоставленный файл и не подгоняй expected под фактический результат**. Красный тест, корректно выявляющий дефект, допустим.

## Часть B — Python Core: покупка предмета

Реализуй самостоятельно в `week03/solutions/python_core_19.py`:

```python
def buy_item(coins: int, price: int, inventory: list[str], item_name: str) -> dict:
    ...
```

**Контракт:**

- `coins` — `int` (не `bool`), `coins >= 0`: монеты игрока до покупки.
- `price` — `int` (не `bool`), `price > 0`: цена одной единицы предмета.
- `inventory` — список строк; каждая строка непустая. Пустой список допустим. Повторяющиеся названия предметов допустимы.
- `item_name` — непустая строка. Пробелы не обрезать; строка из пробелов считается непустой.
- Если любой аргумент нарушает правила типов или значений — выбросить `ValueError`.
- Если `coins < price`, выбросить `ValueError` (недостаточно монет).
- Иначе вернуть **новый словарь** с **ровно двумя ключами**:
  - `'coins'`: оставшиеся монеты (`coins - price`);
  - `'inventory'`: **новый список** из исходных предметов в том же порядке и купленного `item_name` в конце.
- Не изменять исходный `inventory`, включая случаи успешной и неуспешной покупки. При успехе `result['inventory'] is not inventory`.

**Примеры по контракту:**

| Вызов | Ожидание |
| --- | --- |
| `buy_item(100, 35, ['sword'], 'potion')` | `{'coins': 65, 'inventory': ['sword', 'potion']}` |
| `buy_item(10, 10, [], 'key')` | `{'coins': 0, 'inventory': ['key']}` |
| `buy_item(5, 10, [], 'key')` | `ValueError` |
| `buy_item(10, True, [], 'key')` | `ValueError` |

Напиши `week03/solutions/test_python_core_19.py` и проверь:

1. Обычную покупку и покупку ровно на все монеты.
2. Недостаток монет.
3. Невалидные типы/значения аргументов (включая `bool`, пустое имя, неверные элементы `inventory`).
4. Сохранение порядка, допустимость повторов и отсутствие изменения исходного списка; при успехе результирующий список — новый объект.

Для решения не нужны классы, `deepcopy`, внешние библиотеки или мокирование.
