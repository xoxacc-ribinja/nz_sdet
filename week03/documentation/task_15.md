# Task 15 — pytest parametrization

## Цель
Научиться использовать `@pytest.mark.parametrize` и выбирать тестовые данные по контракту. Не исправлять реализацию `delivery_cost`.

## Исходные условия
Используй те же `delivery.py` и контракт из Task 14. Папка проекта: `nz_sdet/week03/`; файл тестов создай как `solutions/test_delivery_parametrized.py`. Импорт: `from week03.input_files.delivery import delivery_cost`.

## Часть A — pytest
1. Напиши параметризованный тест стоимости обычной доставки, минимум с 6 наборами `(weight, expected)`. Обязательно включи обе границы тарифных диапазонов и значения непосредственно по разные стороны границ.
2. Напиши параметризованный тест экспресс-доставки, минимум с 3 наборами данных. Выбери разные тарифные диапазоны.
3. Напиши параметризованный тест невалидного веса, минимум с 3 наборами данных. Ожидаемое исключение — `ValueError`.
4. Запусти `python -m pytest week03/solutions/test_delivery_parametrized.py -v` из корня `nz_sdet`.
5. Не исправляй реализацию. Красный тест допустим, если он обнаруживает нарушение контракта.

## Часть B — Python Core
Без `pytest`, в отдельном файле `solutions/python_core_15.py` напиши функцию:

`def classify_weights(weights):`

На вход приходит список чисел (int или float). Верни новый список строк той же длины, где каждый вес классифицирован по тем же диапазонам, что и стандартная доставка Task 14:
- вес <= 0: `'INVALID'`;
- 0 < вес <= 1: `'SMALL'`;
- 1 < вес <= 5: `'MEDIUM'`;
- вес > 5: `'LARGE'`.

Пример: `classify_weights([0, 0.5, 1, 2.5, 5, 5.1])` должен вернуть `['INVALID', 'SMALL', 'SMALL', 'MEDIUM', 'MEDIUM', 'LARGE']`.

Ограничения: не изменять входной список; не использовать внешние библиотеки; не использовать `map`, `filter` или готовую реализацию из Task 14. Функцию напиши самостоятельно.

## Самопроверка и сдача
Пришли оба файла и лог pytest. Укажи время, использованные источники/подсказки. Проверяем выбор сценариев, понимание параметризации, границы и отсутствие мутации. Не пытайся искусственно сделать все тесты зелёными.
