# Task 14 — Первые тесты на pytest

## Контекст
Ты тестируешь чужую функцию расчёта стоимости доставки. Реализацию менять нельзя: задача — написать тесты и выявить дефекты.

## Файл delivery.py

```python
def delivery_cost(weight, express):
    if weight <= 0:
        raise ValueError('Weight must be positive')
    if weight <= 1:
        cost = 200
    elif weight < 5:
        cost = 400
    else:
        cost = 700
    if express:
        cost += 300
    return cost
```

## Контракт (источник истины)
- `weight` — положительное число, масса посылки в кг.
- При `weight <= 0` должен возникать `ValueError`.
- Стандартная доставка: до 1 кг включительно — 200 рублей; больше 1 кг, но до 5 кг включительно — 400 рублей; больше 5 кг — 700 рублей.
- Если `express == True`, к стоимости прибавляется 300 рублей.
- Если `express == False`, доплаты нет.
- Другие типы аргументов проверять не нужно.

## Задание
1. Создай `delivery.py` с кодом выше, не меняя его.
2. Создай `test_delivery.py`.
3. Напиши не менее 7 отдельных pytest-тестов (`def test_...`) с `assert`, проверяющих контракт, включая границы диапазонов и обе разновидности доставки.
4. Напиши минимум один тест, проверяющий `ValueError`, с помощью `pytest.raises`.
5. Запусти `python -m pytest -v` и пришли `test_delivery.py` вместе с выводом запуска.
6. Если обнаружишь дефект, не исправляй `delivery.py` — тест должен показывать его.

## Подсказка: исключения
```python
import pytest

with pytest.raises(ValueError):
    delivery_cost(0, False)
```
Это пример синтаксиса проверки исключения. Помести его внутрь своей тестовой функции.

## Ограничения
- Пока без параметризации, фикстур, классов и моков.
- Не использовать AI/code completion для написания тестов.
- Можно обращаться к документации за синтаксисом, записав, что смотрел.
- Не изменять исходную функцию.
- Тесты могут падать: это допустимый и ожидаемый результат при дефекте приложения.

- Ожидаемые значения соответствуют контракту, а не текущей реализации.
- Покрыты ключевые границы и express.
- Есть проверка ValueError.
- Найденные несоответствия объяснены без исправления приложения.
- Краткая защита выбора тестовых данных.
