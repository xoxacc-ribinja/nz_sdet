## Часть A — SDET: классификация ответа API

Предоставлена функция `classify_api_response(status_code: int, latency_ms: int, has_body: bool) -> str` в `week03/input_files/api_response_triage.py`.

**Контракт:**

- `status_code` — строго `int` (не `bool`) от 100 до 599 включительно.
- `latency_ms` — строго `int` (не `bool`), неотрицательное время ответа в миллисекундах.
- `has_body` — строго `bool`: есть ли тело ответа.
- При любом неверном типе или значении аргумента выбрасывается `ValueError`.
- Для корректных аргументов результат — ровно одна строка из перечисленных ниже. Правила применяются в указанном порядке:
  1. Статус 500–599 → `'SERVER_ERROR'`, независимо от задержки и тела.
  2. Статус 400–499 → `'CLIENT_ERROR'`, независимо от задержки и тела.
  3. Статус 200–299 без тела (`has_body is False`) → `'EMPTY_SUCCESS'`, независимо от задержки.
  4. Статус 200–299 с телом и задержкой **строго больше 1000 мс** → `'SLOW_SUCCESS'`.
  5. Остальные статусы 200–299 с телом → `'SUCCESS'`.
  6. Все остальные допустимые статусы (100–199, 300–399) → `'OTHER'`.
- Функция не изменяет входные аргументы; внешнего состояния нет.

**Твоя работа:** самостоятельно выбрать и обосновать набор pytest-тестов в `week03/solutions/test_api_response_triage.py`. Сценарии, классы эквивалентности и границы определяешь **сам**, без заранее выданного чек-листа. Тесты должны проверять контракт, а не повторять код функции. Предоставленный исходник может содержать ошибку: **не исправлять его**, не подгонять ожидаемые результаты; обоснованные красные тесты допустимы.

## Часть B — Python Core: обновление складских остатков

Самостоятельно реализуй функцию в `week03/solutions/python_core_20.py`:

```python
def reconcile_stock(current: dict[str, int], deliveries: list[dict]) -> dict[str, int]:
    ...
```

**Контракт:**

- `current` — словарь остатков. Ключи — непустые строки (`''` недопустима, строка из пробелов допустима), значения — целые `int` (не `bool`) от 0 и выше. Пустой словарь допустим.
- `deliveries` — список словарей. Каждый словарь содержит обязательные ключи `'sku'` (непустая строка с тем же правилом о пробелах) и `'quantity'` (строго `int`, не `bool`, **больше нуля**). Дополнительные ключи разрешены и игнорируются. Пустой список допустим.
- Для каждого элемента `deliveries` добавь `quantity` к остатку товара `sku`. Если такого товара нет в `current`, его начальный остаток равен нулю. Если `sku` повторяется в поставках, количества **суммируются**.
- Результат — **новый словарь** с конечными остатками всех товаров из `current` и поставок. Значения — `int`. Если поставок нет, верни новый словарь с теми же парами ключ/значение, что и `current`.
- При неверном типе или значении любого аргумента, ключа, остатка либо элемента поставки выбрасывается `ValueError`.
- Не изменяй `current`, `deliveries` и вложенные словари **ни при успехе, ни при ошибке**. Результат должен быть отдельным объектом: `result is not current`.
- Порядок ключей результирующего словаря **не является частью контракта**.

Создай `week03/solutions/test_python_core_20.py` и самостоятельно спроектируй проверки по всему контракту. Не ограничивайся демонстрацией одного успешного вызова; конкретные тест-кейсы и их число выбираешь сам. Не использовать `collections.Counter`, `defaultdict`, сторонние библиотеки или готовую реализацию от AI.
