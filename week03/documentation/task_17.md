# Task 17 — Build gate и сводка результатов тестов

## Цель
Закрепить тестирование по контракту с `pytest` и написать функцию подсчёта результатов тестового прогона. Использовать уже изученные конструкции Python и явно проверять некорректные входные данные.

## Исходные условия
Рабочая папка: `nz_sdet/week03/`.

Статусы тестов — только строки `"PASSED"`, `"FAILED"`, `"SKIPPED"`, `"ERROR"` (регистр важен). Каждая запись — словарь с ключом `"status"`.

## Часть A — SDET / pytest

Исходный файл: `week03/input_files/build_gate.py`. Функция: `evaluate_build(results, max_failed)`.

**Контракт:**
- `results` — список словарей со статусами из допустимого набора; пустой список допустим.
- `max_failed` — неотрицательное целое число `int`; `bool` не допускается.
- Некорректный тип, структура, отсутствующий ключ или недопустимый статус — `ValueError`.
- Если хотя бы один статус `ERROR`, вернуть `"BLOCKED"`.
- Иначе, если число `FAILED` **строго больше** `max_failed`, вернуть `"REJECTED"`.
- Во всех остальных случаях вернуть `"ACCEPTED"`.
- Входные данные не изменять.

**Задача:** написать тесты в `week03/solutions/test_build_gate.py`, включая граничное значение `FAILED == max_failed`, обычные сценарии, `ERROR`, пустой список и невалидные входные данные. Запустить тесты с `pytest`. Исходную реализацию `build_gate.py` не исправлять: красный тест допустим, если обнаруживает расхождение с контрактом.

## Часть B — Python Core

В `week03/solutions/python_core_17.py` самостоятельно реализовать:

```python
def summarize_results(results: list[dict]) -> dict:
    ...
```

**Контракт:**
- Вход: список словарей, каждый со строковым полем `"status"` из допустимого набора.
- Выход: словарь с пятью ключами `"total"`, `"passed"`, `"failed"`, `"skipped"`, `"error"` и целочисленными счётчиками.
- `"total"` — общее число записей, остальные ключи — количество соответствующих статусов.
- Для пустого списка все пять ключей присутствуют со значением `0`.
- Невалидный список, элемент, отсутствующий или недопустимый статус — `ValueError`.
- Исходный список и вложенные словари не изменять.
- Не использовать `collections.Counter`.

Тесты: `week03/solutions/test_python_core_17.py`. Проверить обычный и пустой наборы, некорректные данные и отсутствие мутации.

## Самопроверка и сдача
Передать реализацию, тесты и лог запуска `pytest`. Для части A тест может быть красным из-за обнаруженной ошибки в предоставленном коде; это не повод менять контракт или исправлять исходный файл.

**Примечание по итогам задания:** в предоставленной реализации `evaluate_build` используется `>=` вместо `>` при сравнении числа `FAILED` с `max_failed`. Это обнаруженное тестами расхождение с контрактом, а не ошибка теста.
