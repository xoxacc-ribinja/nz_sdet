# Decisions

Короткий журнал решений по обучению и организации репозитория. Новые записи добавлять с датой и причиной.

## 2026-10-11 — Перераспределение учебной нагрузки после Task 18

**Решение:** оставить ориентир **3–5 часов в неделю**, не увеличивать его ради ускорения. Сократить долю почти идентичных упражнений и использовать знакомые конструкции в новых контекстах. Сохранять ежедневные 3–4 коротких вопроса без написания кода; возвращаться к пройденным темам с интервалом в несколько дней. При проверке отдельно фиксировать правильность решения и самостоятельность воспроизведения: без подсказок, после наводящего вопроса, после подробного объяснения. Различать непосредственное программирование, инженерную работу (тест-дизайн, анализ, ревью, отладка, Git) и организационные потери времени. Не считать устранение организационных ошибок практикой кодирования. Не вводить дополнительные обязательные критерии PASS.

**Причина:** после Task 18 ученик сообщил, что узнаёт и понимает изученные конструкции при объяснении, но испытывает трудности с их самостоятельным воспроизведением. 2026-10-11 на обучение ушло около четырёх часов, из них непосредственное программирование — не более двух; часть времени заняли организационные ошибки. Нужна не большая нагрузка, а лучшая проверка удержания знаний.

## 2026-10-11 — Ежедневные короткие разминки

**Решение:** после первого обращения ученика за день в учебном чате предлагать 3–4 небольших вопроса на понимание ранее пройденных тем (Python Core, pytest, Git, тест-дизайн). Отвечать можно текстом прямо в чате, без написания и запуска кода. После ответов давать краткую обратную связь с объяснением ошибок. Чередовать темы и иногда возвращаться к старым; не превращать разминку в новое обязательное условие PASS и не вводить через неё неожиданные требования к текущему заданию. Если ученик прямо просит сначала завершить текущую работу, не прерывать её вопросами.

**Причина:** проверять усвоение и перенос знаний между задачами, а не только воспроизведение знакомого шаблона.

## 2026-10-11 — Task 18 и прямой коммит в main

**Решение:** зафиксировать Task 18 как PASS по проверенному контракту, несмотря на один ожидаемый красный тест, выявляющий дефект предоставленной функции. Коммит решения `bf07b00` ошибочно отправлен прямо в `main`; не переписывать историю и не создавать искусственный PR задним числом. Для следующих работ возвращаемся к отдельной ветке и PR. Уточнение контракта из PR #8 слито в `main`.

**Причина:** различать качество учебного решения и нарушение Git-процесса, сохраняя достоверную историю.

## 2026-10-11 — Сначала опубликованное задание, затем код

**Решение:** перед началом каждой новой задачи ассистент публикует Markdown-файл задания в `weekXX/documentation/` и предоставляет ссылку. В файле заранее фиксируются контракт, ограничения и критерии PASS. Новые обязательные требования нельзя добавлять во время проверки; изменения возможны только после явного согласования и обновления документа. Новые конструкции Python сначала объясняются, затем используются в практике. Перед заданиями, ревью и изменениями в репозитории ассистент перечитывает соответствующую документацию GitHub.

**Причина:** Task 17 выполнялся без своевременно опубликованного файла задания; требования и объяснения вводились несвоевременно. Необходимо сделать процесс воспроизводимым и исключить повторение проблемы.

## 2026-10-09 — Скрытые проверки после защиты

**Решение:** иногда проверять сданный и защищённый код на заранее не раскрытых входных данных. До защиты конкретные значения не сообщать; после проверки объяснять результат.

**Причина:** оценивать перенос навыка на новые случаи, а не только прохождение известных примеров. Проверки не должны добавлять требований вне согласованного контракта. Нельзя выдавать неисполненный тест за успешно пройденный.

## 2026-10-09 — Публичное руководство по Python

**Решение:** подготовить краткое самостоятельное руководство `docs/CODE_STYLE.md` для новых учебных работ; не переносить исходный подробный документ целиком.

**Причина:** публичному портфолио нужны применимые правила без лишних специфических деталей.

## 2026-10-09 — Согласованные критерии Task 15

**Решение:** зафиксировать принятые в ходе занятия 5 обычных, 5 express и 2 невалидных кейса; не пересматривать ранее принятый PASS задним числом.

**Причина:** критерии изменялись в процессе, а исходный Markdown не был обновлён.

## 2026-10-09 — Не переписывать историю решений при уборке

**Решение:** оставить папки `week01`–`week03` и существующие имена файлов, добавить навигацию поверх текущей структуры.

**Причина:** массовое перемещение сейчас создаст шум в diff и может сломать импорты. Рефакторинг — отдельная задача.

## 2026-10-09 — Документацию менять через PR

**Решение:** организационные изменения готовить в отдельной ветке; `main` не менять до просмотра PR.

**Причина:** изменения видны, обратимы и не смешиваются с учебными решениями.

## 2026-10-09 — Разделить факты и оценку

**Решение:** различать «файл существует», «тест запускался», «тест прошёл», «задание защищено» и «навык удержан».

**Причина:** зелёный лог одной проверки не доказывает качество всего проекта.

## 2026-10-09 — Публичный репозиторий без личных дневников

**Решение:** хранить технический прогресс и обезличенные отчёты; чувствительные сведения оставлять вне публичного GitHub.

**Причина:** историю публичных коммитов трудно полностью очистить после публикации.
