# NZ DAILY — YYYY-MM-DD

> Диагностика **динамики самостоятельного обучения** за отчётный день (обычно предыдущий календарный день, UTC+4). Не перечень PR и не пересказ чата. Источники: доступная история занятий, GitHub и предыдущие отчёты. Приватное — только в чате. Правила — в [AGENTS.md](../../AGENTS.md).

## Главный вывод: что изменилось со вчера / последней проверки?

Один содержательный вывод: какой навык стал устойчивее, что впервые выполнено самостоятельно, где повторилась старая ошибка, какую гипотезу о прогрессе подтверждают факты? Если сравнимых данных нет — «изменение не подтверждено», не «прогресс = 0».

## Progress Board — та же шкала, а не новые проценты

Перед выпуском сравнить **последний доступный датированный Progress Board** с сегодняшними свидетельствами и записями `LEARNING_LOG.md`. Сохранять прежние названия категорий и сопоставимую историческую шкалу. Для Python Core исторически использовались: Python syntax fluency, Data structures, Control flow, Functions, Type hints, Exceptions, File/data parsing, Code structure, Independent coding. Не выдавать оценки прошлой даты за новые измерения.

| Навык | Предыдущая оценка и дата | Новые данные: самостоятельность / помощь | Решение и основание |
| --- | --- | --- | --- |
| Конкретный навык | Источник или «нет подтверждённой оценки» | Факт или «не проверялся» | Сохранить / обоснованно изменить / недостаточно данных |

Достаточно перечислить **навыки с новыми свидетельствами**, а для остальных явно указать, что их оценки не пересматривались. Из-за одного блица, потраченных часов, количества PR или ответа после подсказки баллы не повышать. Не вводить произвольные проценты, разноцветные полосы и несопоставимые шкалы.

## Что доказано и чего не доказано

- **Самостоятельно до подсказки:** конкретный код, трассировка, решение, наблюдение; точные примеры.
- **После подсказки или объяснения:** какая помощь была и что удалось сделать после неё.
- **Раньше → сегодня:** что уже изучали, сохранилось ли знание после паузы, произошёл ли перенос в новый контекст. Если отсроченной проверки не было, это прямо отметить.
- **Граница доказательства:** чтение кода != написание кода; PASS по контракту != устойчивый навык; локальный лог автора != запуск тестов ассистентом != CI.

## Темп и время

Время — только названное учеником или достоверно измеренное, с пометкой приблизительности. Если известно, различать написание кода, размышление, проверку и потери на ошибки процесса. Неизвестное не считать нулём. Скорость сравнивать с прежней только для сопоставимых по сложности задач и уровня помощи. ~12 часов в неделю — гибкий ориентир, без долгов.

## Качество преподавания и GitHub

Как ревью и объяснения повлияли на результат; ошибки ассистента, навязанные условия и административные потери — кратко и отдельно от прогресса ученика. Состояние задач, PR, тестов и CI — только по подтверждённым свидетельствам. Этот раздел не должен вытеснять обучение.

## Вывод для Python Core и NZ/SDET

Что мешает самостоятельности сейчас? Требуется новое объяснение, самостоятельная практика или проверка удержания? Указать **одну следующую точку наблюдения** на основании динамики, а не механически задавать упражнение. До ноября фокус — Python Core; API/UI/SQL, которые ещё не изучались, не являются недостатком сегодняшней работы.

В самом отчёте указать даты и источники сравнения; недоступные источники явно назвать, не изображая их прочитанными. Есть ли связка «раньше → сейчас → источник → самостоятельность → обоснованное изменение/без изменения»? Не придуманы ли время, оценки, тесты или статус PR? При публикации в GitHub использовать отдельную ветку/PR и проверить запись; открытый PR не равен `main`. Учебный код и репозиторий принадлежат ученику; подготовка AI-наставником текста или коммита через аккаунт ученика не означает авторства ученика над этим текстом.
